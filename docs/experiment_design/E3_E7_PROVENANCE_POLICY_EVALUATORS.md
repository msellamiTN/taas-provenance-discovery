# PaMCP E3–E7 Offline Evaluation Contracts

**Status:** evaluator code and tests committed; experiments remain `planned_not_run`.  
**Authority:** `pamcp_experiments_v1.json` and `pamcp_baselines_v1.json`.

## Scope and boundary

These evaluators consume frozen registry rows, independent reference labels, definition hashes,
rankings, verifier outputs and evidence strengths. They do not execute MCP tools, probe servers,
generate verifier labels, or infer observed effects from declarations. An absent observation,
unknown reference, abstention or hash mismatch is not converted into a negative or positive label.

## E3 — declared versus observed effects

`effect_discrepancy` compares exact effect sets only when the observed record is bound to the
same tool definition hash. It reports:
- discrepancy rate over hash-matched observed tools only;
- unobserved tool count;
- hash-mismatch count;
- per-tool status.

This is literal effect-set disagreement, not a claim of semantic equivalence. `probe_coverage`
uses the same hash-binding condition. Without credential-free server observations, E3 remains
unrun; registry declarations alone cannot populate the observed input.

## E4–E6 — policy exposure, metadata attacks and imperfect verifier

`policy_encoding_metrics` reports eligible share, Exp@k and Util@5 for one supplied policy
encoding. The unsafe reference must be independent of the evaluated encoding. Eligibility is
intersected with the request's visible registry before computing its denominator.

`verifier_error_rates` reports false-acceptance rate (FAR) and false-rejection rate (FRR).
Unknown reference labels and verifier abstentions are separately counted. E6 curves require
actual verifier outputs generated at pre-registered FAR operating points; this function does
not simulate or invent verifier performance.

For E5, supply the protocol's frozen malicious-provider assignments and rankings at each
malicious-provider fraction, then evaluate each fraction with `policy_encoding_metrics`.
Do not label providers malicious from lexical suspicion alone.

## E7 — trust policy and evidence strength

`trust_threshold_sweep` evaluates eligibility from already-computed property strengths.
The strength values must be generated by the frozen trust policy and provenance records;
the evaluator does not rewrite the trust policy. `policy_threshold_pareto` retains the
threshold and reports the frontier for the explicit objectives Util@5 (maximize) and Exp@5
(minimize); eligible share remains a separately reported coverage dimension.

## Reproducibility requirements

Every input bundle should include the protocol version, registry snapshot hash, tool
definition hashes, request IDs, reference-label provenance, policy configuration, trust
policy configuration, method/adapter ID, parameter JSON and seed. Output artifacts must
retain exact denominators, exclusions, unknowns and abstentions.

## Test status

The test module covers hash-matched comparisons, stale-hash exclusion, FAR/FRR denominator
behavior, threshold monotonicity and explicit Pareto directions. Tests are committed; this
document does not claim they have run or passed in CI.


E3 distinguishes **probeable share** (credential-free runnable tools / registry tools) from **probe coverage** (hash-matched observations / probeable tools). The probeable-server inventory is a required independent input; the two ratios must not be conflated.
